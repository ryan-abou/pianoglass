ANDROID MANIFEST — WHAT IS IN IT, AND WHAT TO ADD (NOTHING)
============================================================

Short version: do not add anything to, and do not hand-edit,
Assets/Plugins/Android/AndroidManifest.xml. It is correct as checked in.

This file used to tell you to add an android.software.midi <uses-feature>
line. That line was never added, and it is not needed: MIDI works on the
Quest 2 without it. With required="false" it would only ever have affected
store filtering, never runtime behaviour.


1. WHAT THE CHECKED-IN FILE CONTAINS
-------------------------------------

Assets/Plugins/Android/AndroidManifest.xml has, besides the Unity activity
and the Oculus meta-data:

    <uses-feature android:name="android.hardware.vr.headtracking" android:version="1" android:required="true" />
    <uses-feature android:name="oculus.software.handtracking" android:required="false" />
    <uses-permission android:name="com.oculus.permission.HAND_TRACKING" />

It has NO passthrough, anchor or MIDI entries. That is expected.


2. WHERE PASSTHROUGH AND ANCHORS COME FROM
------------------------------------------

Meta's Gradle step (OVRManifestPreprocessor) injects them into the MERGED
manifest at build time, reading Assets/Oculus/OculusProjectConfig.asset:

  - insightPassthroughSupport = Required  -> com.oculus.feature.PASSTHROUGH
  - anchor support                         -> com.oculus.permission.USE_ANCHOR_API

So the file in the repo will never show them. Check the APK, not the file.


3. HOW TO CHECK
---------------

On the headset, after installing:

    adb shell dumpsys package com.ryanabourjeili.pianoglass | findstr permission

Expect com.oculus.permission.USE_ANCHOR_API and
com.oculus.permission.HAND_TRACKING among the granted/requested permissions.

Or on the APK itself, with aapt from the Unity Android SDK build-tools:

    aapt dump badging Builds\PianoGlass.apk | findstr "uses-permission uses-feature"

Expect com.oculus.feature.PASSTHROUGH among the features.


4. NO PERMISSIONS ARE NEEDED FOR MIDI
--------------------------------------

USB MIDI through android.media.midi does not require a runtime permission and
does not show a permission dialog. The MIDI service owns the USB device on
your behalf.

Only the UsbManager fallback route (not used) would need the runtime USB
permission dialog plus
    <uses-feature android:name="android.hardware.usb.host" android:required="false" />
